# Security model

This is an unaudited test-network MVP. See the [recorded verification](evidence/README.md).

The creator selects a designated verifier when creating a job; that authority cannot be substituted later. The verifier is trusted and can approve false work or reject good work. There is no arbitration or slashing. If submitted work receives no verifier response, the creator can refund after the verification deadline. This is an explicit timeout tradeoff. `VERIFIED` cannot be refunded, even after deadlines; anyone can settle to a token account owned by the assigned worker.

The creator can cancel `CREATED`, refund `FUNDED` at or after the claim deadline, refund `CLAIMED` at or after the submission deadline, refund `SUBMITTED` at or after the verification deadline, and refund `REJECTED` immediately. `SETTLED`, `CANCELLED` and `REFUNDED` are terminal. Every funded state has an eventual authorized exit for the committed principal. Deadline actions require chain time strictly before the deadline; expiration refunds require time at or after it. Signer and prior-state checks apply to each transition.

Anchor constraints bind PDA seeds, mint, token program, vault authority and recipients. Transfers are atomic SPL-token CPIs using the job PDA. Token-2022 and freeze-enabled mints are rejected. The fixed escrow principal settles exactly once. Extra tokens sent directly to a vault are not recovered by the MVP, and account rent remains retained.

API writes require a signed wallet challenge bound to domain, wallet, action, exact request-body SHA256, random nonce and a 60-second expiry. A valid nonce is synchronously consumed before asynchronous mutation. Agent-ID ownership is checked atomically in the serialized store. Artifact reads enforce realpath containment, file type and bounded size. The worker treats job text and artifacts as data and never executes arbitrary shell commands or job code.

Signing keys remain in external files with mode 0600 under a restricted directory. Public chain readers contain no private keys, and their signing methods throw. Browser E2E test keys remain in the Node driver; only public keys and signing callbacks reach the browser. The UI and SDK check fresh RPC genesis before signing and reject mismatched profiles. Mainnet requires a separately configured, explicitly enabled profile; no mainnet effects are authorized or verified. The deployed devnet program remains upgradeable until a reviewed release policy changes its authority.

The fixed executor uses Node permissions and explicit resource bounds. Node permission mode is not OS network isolation or a safe boundary for hostile arbitrary executable code. Operator-controlled configuration, signing processes, filesystem and upgrade authority remain trusted. The hosted API adds global request/concurrency limits, bounded challenges and SSE connections, signed upload quotas, immutable hash-named files and SQLite WAL persistence. A one-replica service and API lease protect journal ownership. Worker and verifier use separate wallets, but their trusted parent processes share a Unix UID; role environment filtering does not isolate those signers at the OS level. The devnet faucet holds separate test-SOL and demo-mint credentials, with a lifetime per-wallet quota, global cap, reserve checks and one durable signed transaction per grant. The API's chain-reader wallet cannot sign; the optional faucet is a separate, bounded signing operation. Public deployment at otcs.ai has real wallet/payout/refund/faucet/restart evidence. Both Linux containers and their loader helpers run as UID 1000 with all capabilities dropped; credentials are read-only mounts. This establishes the tested bounded service, not unlimited capacity or mainnet safety.

Dependency audit findings inherited through Anchor, legacy web3 and SPL dependencies remain visible in the review and release evidence. Reachability analysis is not an exemption or a claim of production safety. The prototype exposes neither the Vitest UI server nor marketplace TOML parsing. Production funds require a separately reviewed custody and signing boundary.
